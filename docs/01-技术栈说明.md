# 01 · 技术栈说明

## 一句话

AppTabs 是一个 Windows 桌面 WinForms 应用，用原生 Win32 把已打开的软件窗口嵌入 / 排列在自己的标签工作区中；核心逻辑与界面分离，发布为免安装便携目录。

## 技术栈

| 组件 | 选择 | 用途 |
|---|---|---|
| 语言 / 运行时 | C# / .NET Framework 4.8 | Windows 10 1703+ 自带运行时，便于免安装分发 |
| UI | WinForms | 单窗口宿主、原生子窗口嵌入、自绘标题栏 / 页签 / 弹窗 |
| 平台 | x64 / Windows | Win32 窗口操作、PerMonitorV2 DPI |
| 测试 | 自带控制台断言 | 不引入第三方测试框架；fake + 自建跨进程窗口 |
| 图标 | SVG 源图 + 七尺寸 32bpp ICO | 主窗 / 托盘 / 标题栏统一图标 |
| 脚本 | Windows bat + PowerShell | 构建、测试、开发启动、打包；无第三方构建工具 |

**无第三方 NuGet 依赖**；项目只引用 .NET Framework 自带的 `System.Drawing` / `System.Runtime.Serialization` 等程序集。

## 分层

```text
src/AppTabs.Core   纯策略、窗口身份、Win32 接管 / 还原、恢复日志、设置与库存储
src/AppTabs.App    WinForms 主窗、标签栏、对话框、托盘、键盘钩子
tests/AppTabs.Tests 无框架控制台断言、fake、自建窗口、离屏界面检查
scripts/           构建 / 开发 / 打包 / 图标生成
assets/            SVG 源图与多尺寸 ICO
```

`Core` 不引用 WinForms，便于用 fake 做纯策略测试；`App` 只做界面编排和原生 API 接线；测试不依赖真实用户软件。

## 选型理由

- **WinForms 而不是 WPF / WebView**：需要直接承载任意第三方顶层窗口，按 HWND 做 `SetParent` / 样式 / 位置 / Z-order 操作；WinForms 的 HWND 模型更直接，也避免引入 WebView2 运行时依赖。
- **.NET Framework 4.8**：Windows 10/11 通常已内置，便携包不需要额外安装运行时；代价是不能使用 .NET 6+ 的部分 API。
- **纯 Win32 封装**：窗口身份、DPI awareness、恢复样式都必须直接控制；不套用第三方 UI 框架的窗口管理。
- **无第三方 NuGet**：减少供应链 / 版本冲突，便携包只包含自身程序集。
- **控制台断言**：测试可在无测试运行器的机器上执行，便于 CI / 本地快速回归；fake 与自建窗口确保不碰用户软件。

## 构建与发布

- 版本号唯一来源：`Directory.Build.props` 的 `Version`；`app.manifest` 的 `assemblyIdentity` 需同步更新，发布文件名从 `Directory.Build.props` 读取。
- 完整构建：`build.bat`（测试 + 打包）或 `powershell -File scripts/build.ps1`。
- 只测试：`test.bat`。
- 开发构建：`dev.bat -BuildOnly` → `.runtime\dev`。
- 发布：`package.bat` → `dist\dev` 的 debug zip、`dist\release\unpack\`、release zip、`SHA256SUMS.txt`。
- 运行：`run.bat` 或 `dist\release\unpack\AppTabs.exe`。

## 已知边界

- 跨进程嵌入不是 Windows 保证的能力；浏览器、Electron、WPF、UWP / 打包应用、自绘窗口需要逐个实测。
- 目标窗口与 AppTabs 的 DPI awareness 不一致时，自动模式会回退到分组（默认无边框）；不会修改目标进程的 DPI 设置。
- 管理员权限的目标软件需要以同等权限启动 AppTabs。
- 目标窗口存在未处理模态框、置顶或未响应状态时，不应尝试接管。
- 异常恢复只能还原仍存活的窗口；已销毁窗口无法复活，未保存内容无法保证。
